# Plan — M2 gaps + full M3, with a depth/lighting graphics pass

**Branch:** `feat/M3-ages` (branched from `feat/visual-overhaul`)
**Spec (binding authority):** `CLAUDE.md` and `PROGRAM_TERV.md` in the repo
root. Relevant `PROGRAM_TERV.md` sections are cited per task — read only
the cited sections, not the whole file.

**User's request (2026-10-25, Hungarian, paraphrased):** finish the M2
gaps, then all of M3. Self-review, subagent driven. Pay special attention
to graphics: the look is very important — it must feel deep and dynamic,
"3D". Plenty of time and tokens may be spent on it.

## Global Constraints

These bind every task. Reviewers check them.

1. **Stack:** Phaser 3.80 (WebGL), TypeScript strict (`strict`,
   `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), Vite,
   Vitest, Miniplex ECS, Zustand vanilla store. **No new npm
   dependencies** in this plan.
2. **Language:** code, identifiers, comments, commit messages in English.
   Every player-visible string lives in `src/i18n/hu.ts` (Hungarian) —
   never hard-coded in components, panels or scenes.
3. **Architecture:** the ECS world is the single source of game truth.
   Phaser GameObjects are render proxies only, with no game logic. The
   Zustand store (`src/ui/store.ts`) holds UI state only. Systems are
   classes with an `update(deltaMs)` (match existing systems in
   `src/ecs/systems/`).
4. **Balance values** live in `src/config/balance.ts` (created in Task 2)
   — no stat literals scattered in systems, archetypes or AI.
5. **Art is procedural** (canvas painting in `src/iso/art/`). No binary
   assets are added. All world art follows the lighting contract from
   Task 3 once it exists.
6. **Files stay under ~400 lines.** Split modules rather than grow them.
   `any` is forbidden (except commented 3rd-party interop).
7. **Tests:** pure logic gets Vitest tests (damage formula, research
   effects, projectile motion, age gating, map validation, AI decision
   helpers). `npm run lint`, `npm test`, `npm run build` must all pass at
   the end of every task.
8. **Performance budget:** ≥ 55 FPS on a 96×96 map with 4 players at
   default zoom on the dev machine (WebGL). Texture memory for all
   generated art ≤ 256 MB. Bundle < 2 MB gzip.
9. **Visual direction:** warm dark glass DOM UI (amber `#f5a857`, Inter +
   Cinzel), living animated world. New UI follows `src/ui/hud.css` /
   `src/ui/screens.css` tokens.
10. **Commits:** conventional commits (`feat:`, `fix:`, `refactor:`,
    `docs:`, `test:`), one or more per task, on `feat/M3-ages`. Do not
    push; the controller pushes.
11. **Speed scale:** `PROGRAM_TERV.md` §7 lists speeds in AoE units. The
    game uses `gameSpeed = tableSpeed × 2.75` tiles/s (villager 0.9 →
    2.475), keeping the feel the game was tuned for.
12. **Visual verification:** the dev server runs at
    `http://localhost:5173/` (start `npm run dev` if it is down). In dev
    builds `window.__game` is the `Phaser.Game`. Graphics tasks must be
    checked in the browser with screenshots, not only by tests.

### Task 3: Graphics — lighting foundation (normal maps, sun, day cycle, cast shadows)

**Goal:** the world must read as **lit 3D volume**, not flat paintings.
This task sets the lighting contract every later art task follows.

**Requirements:**
- **Normal maps:** extend the procedural pipeline so every painted
  world texture (buildings, construction sites, trees, rocks, bushes,
  stumps, units) also produces a normal-map canvas of identical size.
  `IsoPainter` knows each face's orientation (left wall, right wall, roof
  slopes, ground, cylinders) — paint the normal alongside the albedo;
  add subtle per-texel normal noise for stone/plank/thatch detail. Units
  and trees can use a sphere/cylinder approximation. Attach the normal
  map via Phaser `Texture.setDataSource(normalCanvas)`.
- **Light2D:** world sprites (terrain chunks with a flat normal,
  decor, buildings, units) use the `Light2D` pipeline. Configure
  `maxLights` in `src/config/game.ts` as needed.
- **Sun + day cycle:** a far, large-radius light (or equivalent)
  approximating a directional sun that moves slowly through a cycle
  (dawn → day → golden hour → dusk → back, ~12 real minutes for a full
  cycle; values in balance/visual config). Ambient colour shifts with
  it. The darkest point must stay readable (never below ~55%
  brightness). At dusk, building windows get warm emissive glow (glow
  sprites, additive blending).
- **Point lights API** `src/iso/art/lighting/LightManager.ts` (or
  similar): persistent lights (forge, chimneys, torches on TC/towers) and
  `flash(x, y, colour, radius, durationMs)` for muzzle flashes and
  explosions (used by Task 6). Pool lights; cap the active count.
- **Cast shadows:** buildings, trees and units cast soft shadows that
  follow the sun direction (projected/skewed silhouette sprites, tinted
  dark, low alpha, blurred look), drawn under the casters and above the
  terrain. Shadow length varies with sun height.
- **Contact shadows / AO:** keep the existing foot shadows; add darkened
  ground around building bases.
- A dev toggle constant to disable lighting (fallback path keeps the
  current look) — in config, not UI.
- Fog of war must still hide/darken correctly over lit sprites.

**Verification:** screenshots at three times of day (dawn, noon, dusk)
of the town area, saved to the task workspace; FPS check zoomed out on
the default map (Global Constraint 8). Report texture memory estimate.
Tests for pure helpers (sun position over time, shadow projection
vector, light pool).

### Task 5: Projectile system (M2.6 logic)

**Spec:** `PROGRAM_TERV.md` M2.6; §7.4 cannon AOE.

- `projectile` component + `src/ecs/systems/ProjectileSystem.ts`.
  Ranged attackers (archer, crossbowman, musketeer, cannon, tower) no
  longer deal damage instantly: when their attack fires (cooldown
  reset in CombatSystem) they spawn a
  projectile with kind (`arrow`, `bolt`, `bullet`, `cannonball`),
  start/end world positions, flight time from distance and kind speed,
  arc height (arrows and cannonballs arc; bullets are near-flat and
  fast), owner, damage payload.
- On arrival the payload resolves with the Task 2 formula against the
  target if it is still alive and within 0.75 tile of the impact point
  (moving targets can be missed by slow projectiles — acceptable and
  realistic). Cannonballs hit every enemy unit and building within 1
  tile of the impact point (Ruling in spec: full damage, no friendly
  fire).
- Pure motion helper (`projectileMotion.ts`: position + height at t,
  tangent angle) with tests; system tests for hit, miss, AOE.
- Minimal rendering hook: RenderSystem (or a small `ProjectileRender`)
  shows a placeholder line so the logic is visible; Task 6 makes it
  beautiful.

**Acceptance:** archers kill units with visible delay; cannon damages a
cluster; tests pass.
